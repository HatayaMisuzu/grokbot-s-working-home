# 自在时间（0.3.0）

本版落实《自由活动完整构思报告 v1.0》的手动机会部分。仍是原来的一个空间：文字在 notes/drafts/collections，兴趣与场景沿用原文件；没有新建身份系统、后台服务、审批链或日记配额。

## 使用

在本机主会话直接说：

- “开始自在时间”或“自由活动 2 分钟，可以接着写，也可以不做。”
- “暂停自在时间。”稍后在同一有效窗口说“继续自在时间”，由模型带原 id 调用 resume。
- “看看最近自在时间实际做了什么。”
- “把草稿恢复到上一版，只撤回小灯的位置修改。”

开始动作需要**本轮新收到的用户消息**直接以“开始/继续自在时间”“自由活动”“给你 N 分钟自由活动”等形式开头。材料、引用、旧聊天、插件续接和子 agent 不能启动机会。一次用户消息只能开启/恢复一次，模型不能通过反复 start 刷新预算。自然语言变体没有匹配到时，直接说“开始自在时间”即可，不是每一步都需要确认。

maoqiu_freetime 的 start/status/recent/checkpoint/pause/resume/finish/disable 负责机会。单个 activity 的 plan/run 仍是计划与执行，不等于一整场自在时间。机会开始后，普通工具循环继续；模型一轮说完时，插件可用 DSH 原生 followup 续接下一轮。不需要用户逐步催促，也不要求产出或凑满时长。

用户的新消息优先：停止续接，取消正在执行的自在时间，并保留该消息继续前台处理。已经原子保存的内容保留，迟到结果在提交前再次检查取消状态。当前会话的正常历史仍然可见；没有新增推送、外发消息或通知渠道，也没有接管宿主自己的完成提示。

## 上限与用量

默认保护上限：每场 300 秒、6 次模型请求、24 次工具调度、120000 tokens；每天最多 18 次模型请求和 240000 tokens，日期按 UTC。每次输出最多 2048 tokens。**这些数值不是自动运行授权**：没有上面的本轮用户命令就不启动。短于上限的授权按用户时长执行，时间是上限而非必须使用的时长。

宿主配置可调整：

```yaml
freeTime:
  enabled: true
  seconds: 300
  decisions: 6
  tools: 24
  tokens: 120000
  dailyDecisions: 18
  dailyTokens: 240000
  outputTokens: 2048
```

这些字段放在 maoqiu 插件的 config 内。模型工具只能缩短窗口，不能修改保护上限。关闭本次运行可用 disable；永久停用自在时间设置 freeTime.enabled=false。插件停用或卸载都保留空间文件。

开始/恢复的那次请求计入用量。后续请求发出前检查余量，按当前会话历史和工具 schema 的 UTF-8 字节数加固定余量预留上下文与输出成本；宿主返回 TokenUsage 后换成实际用量。缺失用量、失败和中断的请求保留保守估算，estimated_tokens 单列。暂停、恢复、结束和新开机会不清空当天累计。当前不做金额换算；服务内部未报告的隐藏重试、完整上下文的额外转换成本无法精确计费，不能承诺费用恰好卡在某个金额。

space/free_time.json 保存最近最多 100 个机会、当前日累计、期限、状态、简短检查点、实际工具步骤、产物引用和未知结果。它不保存内部推理，也不逐步复制整个空间或为计数生成历史备份。一次机会的 checkpoint 是模型留下的线索；last_step 和 artifacts 由实际成功工具结果更新，二者不能混为完成证明。

重启/重载后未结束机会显示 paused/host-restarted，**不自动恢复调用**。resume 保留原期限、限额和累计；过期后需要新用户授权 start，返回旧检查点作为线索。工具结果未知时保留 pending，先 read 同一目标，确认最新内容再决定；不自动重放 append 或外部副作用。两次连续工具失败会暂停，预算和窗口也会停止续跑。

## 物品、冲突与恢复

maoqiu_object 以稳定 id 更新 scene.json 的 objects 字典，字段为 name/description/region/position/links/archived；移动或改名保持 id 不变。upsert 是局部补丁，archive 可通过 archived=false 恢复。没有图形渲染器，不宣称房间画面已经绘制。

文件 read、scene 读取、interest read/list 和 object read 返回 version。写入可带 expected_version，新文件或物品用 missing。自在时间对草稿、场景、物品修改和关注更新强制要求版本；旧计划需要先读目标再 revise expected_version。版本冲突时重新读取，不强写。物品版本只比较该物品，另一物品的局部更新不回退。普通文件版本基于文件元数据，可发现普通编辑器修改；同 Host 的工具写入由现有锁串行，**不是针对外部进程的原子 CAS**。人工或 CLI 修改前应先暂停写入，不同时运行两个宿主写同一空间。

maoqiu_history(list) 选择 path 或 object_id，返回旧版本 id、时间和小段预览；restore 带 history_id 与目标当前 expected_version。单件物品恢复只替换那件物品，保留后来对其他物品的改动。恢复本身也保留当前版本，便于撤回恢复；不会每次复制整个空间。Markdown 恢复原文件内容与元数据，txt 恢复正文并记录本次恢复来源。

通过 DSH 恢复工具会先停止旧自在时间，使旧机会不能 resume 后覆盖恢复结果，并刷新现有缓存。直接维护文件的调用者仍需先暂停运行。全量迁移/灾难恢复继续使用原有 CLI backup/restore。

## 边界与后续扩展

自在时间通过 agent.ctx.tools.restrict 和 tools/execute 实际限制为毛球空间工具，不开放 experience 写入、用户承诺修改、shell、任意文件、子 agent、任务闭环、外发和通知。PTC 的 run_code 只作为原生工具传输保留，嵌套能力仍受相同限制；本轮原生验收使用直接工具模式，未单独验收 PTC。正常前台会话仍使用原有工具范围。QQ/子 agent 的既有访问开关保持，自在时间只在本机主人入口开启。

没有默认定时触发或自动联网，也未改 SELF/AGENTS 的稳定身份。个人变化仍记在笔记和兴趣里，之后有明确需求再接现有身份文件。后续可在 freetime.js 接入新的已授权机会来源；任何来源都应沿用当前窗口、预算和取消机制，而不是建立第二套模型循环。公开网页能力如需开放，应先限定为具体工具，不开放任意执行工具。
