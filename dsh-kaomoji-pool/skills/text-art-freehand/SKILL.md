# 自由字符画

你是画面的作者。根据本轮交流自己决定主题、视角、姿态、物件和布局；`text_art` 是纸、尺子、图层和橡皮，不会替你理解题材，也不会把一句自然语言自动变成图。不要把用户的描述直接当成“绘图 prompt”塞给工具，然后等待它生成。

只在轻松聊天、毛球陪伴、空间来访或获准的创作中使用。遇到工作或严肃话题自然停止装饰。用户要看画时，最终回复必须展示作品，不能只说已经画好。

## 从意图到画面

1. **选出画面的主语和动词。** “抱着月亮睡觉的小家伙”的重点是抱的姿势、月亮和睡意，不是堆满星星。先决定哪两三个形状能让这个动作成立。
2. **决定视角和体量。** 正面适合表情，侧面适合动作，斜视适合小屋与物体。闲聊小图通常 16–36 列、4–12 行；复杂作品按需要展开。不为了炫技堆尺寸。
3. **先画外轮廓，再放内部结构。** 用粗略轮廓定比例，确认主体像什么，再加眼睛、手、门窗、物件。角色不是“一个颜文字 + 一句标题”；让身体朝向和手脚真正表达动作。
4. **用负空间确认轮廓。** 耳朵与背景、手与杯子、前景与后景之间留出空白。两个物体贴在一起时，决定接触处谁在前面，不要把两边边线原样叠满。
5. **最后加情绪和细节。** 用眉眼方向、身体倾斜、动作线和少量点缀表达。近景细节稍多，远景更简略；不把整个背景填满。
6. **检查实际字符。** 读回成品，观察左右轮廓、留白、物件接触和画面重心。工具只能检查结构，不能证明“像”“可爱”或“有故事”；这些由你评估。

## 常用造型方法

- 水平边：`_ - ~`；垂直边：`| ! :`；斜边：`/ \`；圆润转折：`( ) . ' ,`。
- 同一个斜面不要随机切换方向。轮廓的断开可以是高光或遮挡，但要有意图。
- ASCII 字符通常比行高窄：看起来接近圆的形状，在字符列数上通常比行数更多。椭圆工具只是草图骨架，可用自绘 text 图层修出自然轮廓。
- 表情变化除了嘴巴，也可改眼睛闭合程度、目光方向、头部倾斜。修改同一角色时保留能辨认它的耳朵、头身比例、尾巴或标记。
- 用小的方向变化表达动作；需要抱物时，让手出现在物件两侧或前面，让物件重心靠近身体。
- 山、水、船、建筑、植物、抽象幻想都可以画。没有对应“素材名”不会限制题材。

## 怎样从零写出轮廓

不要从“我记得哪幅类似的画”开始。先选几个锚点：头顶、两侧最宽处、脚底、视线和物件接触点。在你选定的列/行范围内，为每一行决定主体左边界和右边界；只写这两条边，先让大外形成形。

弧线让相邻行的缩进逐渐变化；直斜面让缩进变化保持规律。然后给耳朵、手、枝条等凸出部分另留位置；给杯口、窗洞、角色之间的空隙保留负空间。最后才加内部线条。动作读不出来时，优先调整锚点、接触点或视角，而不是增加标点装饰。

复杂画可以先 `draw` 一版结构，读回后用 `edit` 修正局部。每轮修改围绕用户要求的变化；已有画面可读时直接交付，不需要为了流程反复调用工具。更细的按行轮廓、斜率和曲线构造方法见 `guide(topic="contours")`。

## 路径一：直接写画

在脑中安排各行，自行写出多行 text，然后调用：

`text_art(action="draw", text="你自行绘制的原始多行字符")`

工具保存缩进、空格和换行，返回 artId 与成品。后续用 `edit`、同一 artId 和新的全文修改。要从历史中恢复原文，用 `inspect`。不要在没有返回结果时自造 artId。

适合轮廓复杂的小动物、自由线稿、精心安排的符号画。工具不会自动把原文变成图层；需要局部图层操作时，最初就使用下一条路径。

## 路径二：自己搭建图层

`draw` 的 `objects` 是按顺序绘制的通用对象：

| kind | 必需/主要字段 | 用途 |
|---|---|---|
| text | 自绘 text；x/y 默认 0 | 任意手绘局部、对白、轮廓和细节 |
| line | x/y、x2/y2；可选 char | 自定起终点的线，不限题材 |
| box | x/y、width/height；可选 char/fill | 窗、框、墙、分格；不是角色模板 |
| ellipse | x/y、width/height；可选 char/fill | 通用椭圆轮廓，可继续修饰 |

坐标从左上角 `(0,0)` 开始，x 向右，y 向下；单位是显示列和行。每层起一个描述内容的 id，例如 `near-roof`、`left-hand`。不指定画布尺寸时，按图层范围自动计算；明确 width/height 后，越界会报错，不会悄悄截掉图形。

text 图层默认空格透明，适合叠加细节。用 `transparent:false` 可以用空格盖掉背景或清空局部。后面的对象覆盖前面的对象；处理手、物件和背景的前后关系时，利用这个顺序。

原语字段示意（仅说明坐标，不是完整作品）：

```json
{"id":"custom-edge","kind":"line","x":2,"y":3,"x2":12,"y2":6,"char":"/"}
```

不要直接复制示意当成用户要的画。你需要为本次构图确定每一层的形状和位置。

## 连续修改

- `edit(artId="实际 id", changes=[{"id":"已有图层","x":新位置}])` 移动图层。line 移动时还需同步更新 x2/y2。
- changes 中为已有 id 更新字段；新 id 需带 kind 和所需绘制字段，将其加在最前景；`{"id":"某层","remove":true}` 删除。
- 若新内容超出原画布，在 edit 顶层同时给新的 width/height。
- 原文画用 `edit(artId=...,text=修改后的完整原文)`。图层画也可整幅替换成原文，但之后不再拥有旧图层。
- `inspect` 取回图层数据；不要假设记忆里所有坐标仍然正确。
- 每次修改生成新 artId，旧画短期保留。缓存只保留当前 agent 最近几幅；跨会话需要通过已有文件或毛球空间工具保存并回读原文。

## 构造示范（看过程，不要照抄成品）

下面三段只演示“从要求到行”的思考顺序。每次都要为本轮要求重新构图，不要把这些图当素材复用。

**示范 1：小猫抱着月亮睡觉。**
1. 主语=猫，动词=抱+睡。必须读得出来的三件事：猫耳、闭着的眼、身体两侧环住一弯月亮。
2. 锚点：耳尖第 0 行；脸第 1–2 行；月牙放在身体前方，第 3–5 行；爪子落在月牙两侧。
3. 先写外轮廓，再写闭眼 `-` 和抱住月亮的爪子 `(` `)`，最后加一个 `z` 说明睡着。

```text
  /\_/\    z
 ( -.- )
 /(  _)\
( | (  )|
 \_\_)_/
```
这里的月牙只用 `(` 和 `_)` 表示，被两只爪子夹在中间。爪子和月牙的接触点就是“抱”。

**示范 2：雨夜里亮灯的小屋。**
1. 主语=小屋，状态=下雨+有灯。必须读得出来：屋顶、窗、窗里的光、方向统一的雨线。
2. 雨全部用同一种斜线 `/`，只撒在屋子四周。窗里填 `#` 或 `*` 表示亮光，和外面的雨形成对比。
3. 屋顶比墙宽一列，看起来有屋檐。地面一行就够。

```text
 /   /  /   /
    _____   /
 / /_____   | [#] |  /
 / |__|__|
 ~~~~~~~~~~~
```

**示范 3：坐在小岛上钓星星。**
1. 必须读得出来：坐着的角色、伸出去的竿、竿尖垂下的线、线末端的星星、脚下的小岛。
2. 竿从手部斜向上伸出（`/`），线从竿尖竖直落下（`|`），星星（`*`）正好挂在线的末端。少了任何一环，“钓”就不成立。

```text
          /|
  (o.o)  / |
  /|  |_/  *
 _/_|_\_
~~~~~~~~~~
```

**反例：说了却没画出来。**
要求“抱着月亮睡觉”，结果画出了睁眼的 `(o) (o)`，没有耳朵，也看不出月亮，只靠配文说“抱着月亮”。错在三处：睁眼和睡觉矛盾；主体的辨识特征（猫耳）缺失；主要物件（月亮）和动作（抱）没有画出来。**配文不能替画面完成任务。** 如果画面里找不到用户点名的东西，就重画，不要用文字补救。

## 画完的自检（逐条过，任何一条不满足就改）

1. **点名的东西都在吗？** 把用户提到的主体、物件、动作、状态（睡、雨、亮灯）逐个在画里指出来。
2. **主体认得出吗？** 至少有一处辨识特征（猫耳、屋顶、竿）。
3. **动作成立吗？** 接触点在不在（爪子贴着月亮、线挂着星星）？眼睛和姿态跟状态一致吗（睡=闭眼）？
4. **画和配文一致吗？** 配文描述的每件事画里都要有；没画出来的不要写。
5. **排版可靠吗？** 轮廓闭合，留白有层次，宽度适合聊天窗口；对齐要求严格时用纯 ASCII。

`check(text=...)` 可以在不保存作品的情况下测量宽度和行数，发现排版问题。ASCII 宽度可按列处理；Unicode 受字体影响，工具报告的只是估计。宽了就改构图或改成纵向排列，不要从右边裁掉半个角色。

最终展示使用工具返回的纯文本代码围栏。不要加行号、Markdown 转义或改写空格。画外配一两句自然的话即可。中文对白默认放画外，或使用独立框体并计算宽度。

若需要更多技巧，再按需调用 `guide(topic="contours")`、`guide(topic="composition")`、`guide(topic="shading")` 或 `guide(topic="unicode")`。无需每幅画重读所有材料，也不必为简单小图强制跑一串工具。
