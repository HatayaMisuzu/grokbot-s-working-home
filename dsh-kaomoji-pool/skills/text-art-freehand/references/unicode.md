# Unicode 与显示

ASCII 的可打印字符在等宽字体下可精确按列组合。Unicode 的显示宽度与实际字体有关；本工具按字素分段，估计 CJK 和 emoji 占两列，常见组合字符附着于同一字素，其他符号按一列处理。

这不是所有字体上的像素测量。符号、框线、emoji、组合字形可能触发字体回退；工具的列数通过也不能证明画面在 DSH 中完全对齐。遇到问题，先改用经过观察的符号集合，或将严格对齐的主体改成 ASCII。

text 图层可以包含多列字素；线条、边框的 char 和 fill 只接受单列字符。对同一格的覆盖会先清除被覆盖的多列字素，避免留下半个汉字的延续格。

不要用不可见字符、双向控制符或特殊空格来“偷偷对齐”。Tab 会展开为四列制表位；ASCII 空格本身就是最可靠的留白。画面原文保留首尾空白，不使用颜文字的 NFKC 或去空白归一化。

中文正文默认放在画外。确需框内文字时，按估计列宽留余量，先在实际 DSH 里看一遍。代码围栏只负责保护文本结构；它不保证宿主一定使用合适字体。

参考：Unicode UAX #11 https://unicode.org/reports/tr11/ ，CommonMark 代码围栏 https://spec.commonmark.org/0.31.2/#fenced-code-blocks 。
